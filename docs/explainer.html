01 — Overview

What this system does

A fixed CCTV road camera goes in. Two outputs come out: a timestamped list of traffic events, and — frame by frame, as the video plays — a rising-or-falling number that says how likely an accident is about to happen.

14
Official event classes

From accident and wrong_way to fire_smoke. Every clip gets scored against a hidden, human-annotated set of these.

8 / 14
Classes automated today

Detector + tracker + hand-written rules, with no calibration step. The rest need per-camera calibration we don't have yet — see Class coverage.

0
GPUs / labels required

The default pipeline is classical computer vision (background subtraction). A learned detector is a documented, optional upgrade.

02 — Evaluation

How the hidden test set scores a submission

Two independent scores, blended into one number. Understanding the formula is what tells you which mistakes actually cost points.

Score A — event detection (70%)

For each class, at IoU thresholds 0.3 / 0.5 / 0.7, match predicted segments to ground truth by overlap. Unmatched predictions are false positives; unmatched ground truth is a miss.

Score_A = mean over classes( mean over τ∈{0.3,0.5,0.7}( F1(class, τ) ) )

Score B — accident anticipation (30%, bonus)

Only accident events count. A risk curve is scored on ranking quality (AP), whether its alarms line up with real accidents (F1), and how early the alarm fires (mTTA).

Score_B = 0.4·AP + 0.4·F1_alarm + 0.2·(mTTA/10s)
Why boundaries matter more than they look: reporting a 5-second crash as the whole minute around it fails IoU ≥ 0.3 against most real ground-truth segments. Tight start/end timing is worth more than catching the event at all.

calibration tipA risk score of 0.5 is defined to mean "an accident is about to start within the 5-second horizon." src/risk.py's time-to-collision term is calibrated directly to that point.

03 — Architecture

Part A — offline event detection

Runs once per video, with the whole clip available. Every finished vehicle/person track gets checked against eight rules; matching stretches of time become events.

03 — Architecture, continued

Part B — causal accident risk

The harness hands over one frame at a time, in order. Nothing downstream is allowed to see a frame before its timestamp arrives — that's what makes an early-warning score meaningful.

04 — Coverage

Which of the 14 classes actually fire today

Eight classes have a genuine, camera-agnostic signal. Six need information this pipeline doesn't have yet — a calibrated stop line, signal state, or lane geometry — so they're wired as an off switch rather than a guess.

05 — Repository

What's in the repo, and why

Required interface

  • solution.py — detect_events(), RiskEstimator
  • run_submission.py — folder of videos → predictions.json, one process per video so the time budget can actually be enforced
  • evaluate.py — format check + Score A / Score B / model score, re-derived from the spec and checked against hand-built examples

Pipeline code (src/)

  • detector.py — MOG2 motion detector (default) + optional YOLO
  • tracker.py — greedy IoU multi-object tracker
  • road_model.py — hull + dominant flow, shared by A and B
  • rules.py / risk.py — the two rule sets above
  • eda.py — runs the moment real samples exist

Also required by the brief

website/ — team page, approach, EDA, live local demo, report (placeholders marked where real data doesn't exist yet). docs/REPORT.md — full write-up: what worked, what didn't, next steps.

06 — Honesty check

Status, in one place

Verified working

detect_events and RiskEstimator run end-to-end on a real .mp4 without crashing, inside the 3× time budget on CPU. The harness and evaluator were checked against hand-built ground truth and reproduce the spec's F1/AP/alarm formulas exactly.

Not yet tuned

Every threshold (10s dwell, 135° heading, IoU-overlap, TTC scaling) is a reasoned default, not a fitted one — there is no real camera footage or ground truth to tune against yet.

Open gaps

6 classes need calibration data. Vehicle/person split is a geometry guess without a real detector. Accident/near_miss use 2D box overlap with no depth cue.

Full detail in docs/REPORT.md — including the ranked next-steps list (get real samples → annotate a dev set → retune against evaluate.py → swap in YOLO → calibrate the remaining 6 classes).
